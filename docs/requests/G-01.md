### G-01.2 · Bootstrap: η σύνδεση πύλας → πραγματικό plugin

**Αιτία #1 — dependency:** το `@capacitor/local-notifications` είναι στο `apps/mobile/package.json`
(εκεί είναι εγκατεστημένο, επαληθευμένο: `apps/mobile/node_modules/@capacitor/local-notifications@8.3.1`).
Το adapter του `packages/adapters-capacitor` το δέχεται ως **δομική πύλα**, επειδή το πακέτο
δεν μπορεί να προσθέσει dependency (κανόνας lane, §3.3).

**Αιτία #2 — dependency:** το `apps/mobile` **δεν** έχει στο `package.json`/`tsconfig.json`
το `@dps/adapters-capacitor` (μόνο το `@dps/core`). Δεν μπορώ να το προσθέσω· είναι config.

**Ακριβές patch (2 αρχεία config + 1 αρχείο bootstrap):**

1. `apps/mobile/package.json` → στο `dependencies`:
   ```json
   "@dps/adapters-capacitor": "workspace:*",
   ```
2. `apps/mobile/tsconfig.json` → στο `references`:
   ```json
   { "path": "../../packages/adapters-capacitor" }
   ```
3. Νέο αρχείο **ή** επέκταση του `main.tsx` (του stream D):

   ```ts
   // apps/mobile/src/eidopoiiseis/sindesi.ts  (ΝΕΟ, δικό μου path — μπορώ να το γράψω
   // μόλις εγκατασταθεί το dependency· σήμερα δεν μπαίνει στο build γιατί λείπει το dep)
   import { LocalNotifications } from '@capacitor/local-notifications';
   import { CapacitorEidopoiiseis } from '@dps/adapters-capacitor';
   import { ok } from '@dps/core';
   import type { EidopoiisiYpiresies } from './eidopoiiseis-typoi.js';

   export function dimiourgise_ypiresies_eidopoiseon(): EidopoiisiYpiresies {
     const e = new CapacitorEidopoiiseis(LocalNotifications);
     return {
       zitise_adia: () => e.zitise_adia(),
       zitisi_adias: () => e.zitisi_adias(),
       programmatise_dokimi: (otn, _lepta) =>
         e.programmatise([
           { kleidiEnotitas: 'dps-dokimi', titlos: 'Δοκιμή ειδοποίησης', soma: 'Λειτουργούν οι τοπικές ειδοποιήσεις.', otan: otn },
         ]).then((a) => (a.ok ? ok(a.timi[0]) : a)),
       akiro_ol: () => e.akiro_ol(),
       lista: () => e.lista_programmatismenon(),
     };
   }
   ```

   Το δεδομένο είναι **δομικά συμβατό** (τα ονόματα των μεθόδων του plugin είναι
   `schedule`, `cancel`, `cancelAll`, `getPending`, `checkPermissions`,
   `requestPermissions`, `registerActionTypes` — όπως στο verified
   `apps/mobile/node_modules/@capacitor/local-notifications/dist/esm/definitions.d.ts`),
   οπότε το `LocalNotifications` ικανοποιεί τη `EidopoiiseisPugi` χωρίς cast.

4. **Σύνδεση από τη σελίδα Ρυθμίσεων** (προτεινόμενο, ώστε να μην ζητηθεί νέα κάψουλα):
   στο `apps/mobile/src/othoni/rythisies/rythisies.tsx`, στην κάρτα «Ειδοποιήσεις»:
   ```tsx
   <Link to="/eidopoiseis" className="pilegma pilegma-entono" data-testid="rythisies-eidopoiseis-othoni">
     Ρυθμίσεις ειδοποιήσεων
   </Link>
   ```
   (απαιτεί προσθήκη του `<Route>` της G-01.1· **επιλέξτε ένα** από τα δύο.)

### G-01.3 · Προαιρετικό: `packages/adapters-capacitor` να κηρύξει το ίδιο dependency

Αν προτιμάτε ο adapter να εισάγει το plugin απευθείας (όπως κάνουν `storage`/`http`/`mystika`),
προσθέστε στο `packages/adapters-capacitor/package.json`:
```json
"@capacitor/local-notifications": "^8.3.1"
```
και μετά ο `EidopoiiseisPugi` μπορεί να αντικατασταθεί από το `LocalNotificationsPlugin`.
**Δεν απαιτείται** — η δομική πύλα λειτουργεί και δοκιμάζεται χωρίς δίκτυο όπως είναι.

### 4.1 `probe.ts` — ΣΚΑΣΜΕΝΟ ΤΟ ROOT BUILD (διορθώθηκε)

Το untracked `packages/adapters-capacitor/src/eidopoiiseis/probe.ts` έκανε
`import { LocalNotifications } from '@capacitor/local-notifications'`, ενώ το πακέτο
**δεν** έχει το dependency → `TS2307` και **το `npx tsc --build` στο root έβρισκε** πριν
ξεκινήσω. Το αρχείο ήταν μέσα στο δικό μου ownership glob, οπότε το διέγραψα (δεν ήταν
committed, άρα δεν χρειάστηκε αρχείο). **Το root `tsc --build` είναι πλέον exit 0.**

### 4.2 `pnpm-lock.yaml` — τροποποιημένο ΠΡΙΝ ξεκινήσω

Το `git status` έδειχνε ήδη ` M pnpm-lock.yaml` στο πρώτο μου `git status` (πριν γράψω
οτιδήποτε). Δεν το άγγιξα και δεν το εγκατάστασα σε κανένα commit μου. Αν είναι από άλλον
lane και δεν πρέπει να μπει, χρειάζεται απόφαση του integrator.

## 5. Σχεδιαστικές αποφάσεις (για review)

1. **Δομική πύλα αντί άμεσου import του plugin.** Το πακέτο δεν μπορεί να προσθέσει
   dependency (§3.3). Ο προσαρμογέας δέχεται το αντικείμενο του plugin, οι υπογραφές
   αντιγράφονται ακριβώς από τα verified `.d.ts` της 8.3.1 (μηδενικό μάντεψα, §3.7).
   Τα tests δίνουν ψεύτικο αντικείμενο — ίδια αρχή με τα mocks του `@capacitor/filesystem`.
2. **`MEGISTOS_ARITHMOS_EIDOPOIISEON = 60`** από το `statheres.ts` του core (όχι μαγικός
   αριθμός). Το iOS κρατάει 64 pending· κρατάμε περιθώριο 4. Πέρα από το όριο → `PROYPOLOGISMOS`.
3. **Deterministic id**: FNV-1a 32-bit μάσκα σε 31 bit. Ίδια ενότητα → ίδιο id σε κάθε
   εκτέλεση, άρα ο χρήστης ακυρώνει με το κλειδί της ενότητας, όχι με αποθηκευμένο id.
4. **D7**: το σώμα ελέγχεται για πρότυπα μυστικών (`password`, `κωδικ`, `api_key`, `token`,
   `bearer`, `authorization`, `cookie`, `session=`, `secret`) **πριν** το προγραμματισμό και
   απορρίπτεται με `MI_EGKYRO_SXIMA`. Το μήνυμα σφάλματος δεν παριχνά το σώμα.
   Η καταγραφή (`KatagrafiPyli`) παίρνει **μόνο αριθμούς** (`eidopoiiseis: <n>`) — ποτέ
   τίτλος, σώμα ή κλειδί ενότητας.
5. **`prompt` ≠ `granted`.** Ο προγραμματισμός με άδεια `prompt` επιστρέφει `AKYROTHIKE` και
   **δεν** ζητά άδεια κρυφά (μόνο από κόμβο του χρήστη). Η οθόνη λέει ρητά «δεν έχει δοθεί».
6. **`getPending` που αποτυγχάνει → `MI_YPOSTIRIZOMENO`, όχι κενή λίστα.** Μια ψευδής
   κενή λίστα θα έκανε την οθόνη να πει «δεν υπάρχουν υπενθυμίσεις» ενώ υπάρχουν (§3.9).

## 6. Υποθέσεις / ανοιχτά

- **Action types σε background:** η `registerActionTypes` καταχωρεί μελέτη/επανάληψη/σήμερα,
  αλλά η εκτέλεση ενέργειας σε background JS **δεν** υλοποιείται από αυτό το lane (θέλει
  σύνδεση scheduler, κάρτα P2). Το fallback είναι το ίδιο με το brief: ο scheduler
  ξανασχεδιάζει την επόμενη μέρα.
- **Παραμετροποίηση αποθήκευσης:** η επιλογή λεπτών ζει στην κατάσταση της οθόνης. Η
  αποθήκευσή της στο `rythmiseis.json` (§5.3) θέλει πρόσθετο πεδίο στο `Rytheseis`
  (`apps/mobile/src/apothiki/apothiki-typoi.ts` — ownership I3)· **δεν το άγγιξα**.
  Αν το θέλετε, το στέλνω ως αίτημα G-01.4.
- **In-app scheduling of ενότητες:** ο adapter δέχεται `AitimEidopoiseis` με `kleidiEnotitas`,
  `titlos`, `soma`, `otan`. Ο scheduler (P2) είναι αυτός που αποφασίζει πότε και για ποιες
  ενότητες — αυτό το lane δεν επιλέγει χρόνους μελέτης.
