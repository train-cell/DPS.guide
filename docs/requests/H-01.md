## 3. Σημαντικές αποφάσεις (για review)

1. **Χωρίς `commander`** (όπως ζητήθηκε): parsing με `process.argv` μόνο με built-ins.
2. **Μοντέλο**: `--montelo` → `<riza>/rythmiseis.json` → σφάλμα. Ποτέ hardcoded, ποτέ
   κρυφό default. Οι εντολές χωρίς LLM τρέχουν και χωρίς μοντέλο· αν ζητηθεί από αυτές
   LLM κλήση, επιστρέφεται σφάλμα (`MiOrismenoMonteloLlmPyli`).
3. **Cache LLM**: δεν εφαρμόζω `me_cache` του `@dps/ai` στο CLI. Το §4 θέτει το cache
   στο `packages/pipeline` («ορχήστρωση, idempotent βήματα, cache»), και μόνο το
   pipeline ξέρει τη διαδρομή cache ανά μάθημα (§5.3). Αν δεν το κάνει το pipeline,
   χάνεται το cache — **χρειάζεται επιβεβαίωση** (βλ. H-01 #4).
4. **`syndesi` είναι μόνο ανάγνωση**: διαβάζει μυστικά (keyring → env fallback) και δεν
   γράφει ποτέ στο keyring. Δεν υπάρχει ακόμα βήμα onboarding που να τα αποθηκεύει.
5. **Έξοδος**: stdout = αποτέλεσμα, stderr = σφάλματα και logs του pipeline. Σε
   `--json` η έξοδος είναι μία εγγραφή στο stdout.
6. **Άγνωστη εκτέλεση**: κάθε σφάλμα (άγνωστη εντολή, λείπον όρισμα, `Sfalma`, εξαίρεση
   adapter, άγγνωστη δομή σφάλματος) γίνεται κανονικό `Sfalma` + exit 1. Καμία unhandled
   rejection, καμία ψεύτικη επιτυχία.

## 4. Αιτήματα (εκτός ownership — δεν τα άγγιξα)

### H-01 #1 — ΜΠΛΟΚΑΡΙΣΤΙΚΟ: typo στο `packages/pipeline/src/index.ts` (δεν είναι δικό μου)

`npx tsc --build apps/cli` **αποτυγχάνει** σε 9 σημεία, όλα στο pipeline:

```text
packages/pipeline/src/index.ts(66,10): error TS2552: Cannot find name 'mi_yploadio'.
                                           Did you mean 'mi_yploadipo'?
… (66, 74, 82, 90, 98, 106, 113, 121, 128)
```

Η βάση ορίζει στη γραμμή 47 τη συνάρτηση `mi_yploadipo(...)`· στις 9 κλήσεις γράφτηκε
`mi_yploadio` (λείπει το `i`). Είναι στο `HEAD` (το `git status` δεν δείχνει το
`packages/pipeline` ως μεταβαλλόμενο), άρα το έφερε το CONTRACT stub του stream/F.

**Ζητούμενο:** διόρθωση των 9 `mi_yploadio` → `mi_yploadipo` στο
`packages/pipeline/src/index.ts` (owner του `packages/pipeline/**` = I1/stream/F).

**Συνέπεια:** τα tests του CLI περνούν (το vitest κάνει transpile χωρίς typecheck),
αλλά το typecheck του `apps/cli` (και κάθε project που κάνει reference στο pipeline)
παραμένει κόκκινο μέχρι να διορθωθεί. **Δεν το άλλαξα**: είναι εκτός `apps/cli/**`.

### H-01 #2 — ΜΠΛΟΚΑΡΙΣΤΙΚΟ: `bin` σε αρχείο TypeScript δεν εκτελείται

Το `bin` δείχνει στο `./src/index.ts` (όπως ζητήθηκε). Το Node 24 κάνει type stripping
χωρίς bundler, **αλλά δεν ξαναγράφει τις προδιαγραφές `.js` σε `.ts`**:

```text
$ node apps/cli/src/index.ts --help
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../apps/cli/src/argv/statheroi-argv.js'
  imported from .../apps/cli/src/index.ts
```

Δεν είναι ειδικό του CLI — η ίδια αποτυχία υπάρχει στη βάση:

```text
$ node packages/core/src/index.ts
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../packages/core/src/contracts/index.js'
```

**Ζητούμενο (μία από τις δύο, απόφαση του integrator):**

- **(α)** Να δείχνουν τα `main`/`types`/`exports` των packages στο `dist` και το
  `bin` στο `dist/index.js` (το `tsc --build` ήδη παράγει `dist`). Καμία νέα εξάρτηση.
- **(β)** Να προστεθεί ένας TypeScript runner (`tsx` ή αντίστοιχο) ως devDependency
  του root, ώστε το `bin` να τρέχει απευθείας το `src/index.ts`.

Δεν ζητώ εγώ νέο dependency — μόνο επιλογή.

### H-01 #3 — root `tsconfig.json`: να προστεθούν δύο references

Το root `tsconfig.json` σήμερα:

```json
"references": [
  { "path": "./packages/core" },
  { "path": "./packages/extract" },
  { "path": "./packages/adapters-node" },
  { "path": "./packages/adapters-capacitor" },
  { "path": "./apps/mobile" }

```

Λείπουν τα `packages/ai`, `packages/pipeline` και `apps/cli`. **Ζητούμενο:**

```json
  { "path": "./packages/ai" },
  { "path": "./packages/pipeline" },
  { "path": "./apps/cli" }
```

Χωρίς αυτά, το `npx tsc --build` στη ρίζα δεν ελέγχει ποτέ το CLI ούτε το pipeline
(γι' αυτό βγαίνει exit 0 ενώ το `tsc --build apps/cli` κοκκινίζει).

### H-01 #4 — `packages/eclass` (L14/L15) λείπει

Το `EisodosPipeline` απαιτεί `EclassPyli`, αλλά το `packages/eclass` δεν υπάρχει.
Το CLI βάζει `MiYpostirimenoEclassPyli` (κάθε μέθοδος → `MI_YPOSTIRIZOMENO` με σαφή

### H-01 #5 — `ownership.json`: ο lane `stream/H` δεν υπάρχει

`node scripts/check-ownership.mjs --lane stream/H` → `Unknown lane or stream: stream/H`.
Το `ownership.json` έχει `I2: ["apps/cli/**"]` αλλά **χωρίς** `docs/requests/**`, οπότε
ακόμα κι αν τρέξει με `--lane I2`, το ίδιο αυτό το αρχείο θα βγει ως παραβίαση — το
ίδιο θέμα που τεκμηρίωσε το `docs/requests/E-OWN-01.md` για το stream/E.

**Ζητούμενο:**

```json
"stream/H": ["apps/cli/**", "docs/requests/**"]
```

(Το `docs/requests/**` προτεινόμενο για ΟΛΑ ΤΑ streams — είναι ο καθολικός
μηχανισμός αιτημάτων του §3.1.)

### H-01 #6 — `pnpm-lock.yaml`: importer για το νέο `apps/cli`

Το `apps/cli` είναι νέο workspace package, αλλά **δεν έτρεξε `pnpm install`** (το
lockfile είναι απαγορευμένο αρχείο). Για να τρέξουν τα tests του CLI χωρίς να
αγγίξω το lockfile, δημιούργησα **junction** στο `apps/cli/node_modules/@dps/*` →
`packages/*` (ο `node_modules/` είναι στο `.gitignore`, άρα δεν αγγίζει το repo).

**Ζητούμενο:** ένα `pnpm install` από τον integrator για να μπει ο importer του
`apps/cli` στο `pnpm-lock.yaml`. Μέχρι τότε τα junctions κρατούν το lane λειτουργικό.

## 5. Υποθέσεις / ανοιχτά

1. **Οι λειτουργίες του eClass δεν δοκιμάστηκαν ποτέ** — δεν υπάρχει `packages/eclass`
   και δεν επιτρέπεται καμία επαφή με το thales (§3.6). Οι εντολές `mathimata`,
   `sygxronismos`, `analysi`, `run` θα επιστρέψουν `MI_YPOSTIRIZOMENO` μέχρι τότε.
2. **Real smoke test**: μόνο ο owner, με δικά του credentials (κανόνας §3.6).
3. **`--montelo`**: το όνομα του μοντέλου περνάει verbatim στο Gemini. Δεν έχει
   ελεγχθεί με πραγματικό κλειδί (απαιτεί BYOK credentials).
4. **Χρόνος εκτέλεσης**: οι κλήσεις Gemini έχουν `LLM_TIMEOUT_MS = 150000` και
   `MEGISTES_EPANALIPSEIS = 3` από το `@dps/ai`. Ο CLI δεν επιβάλλει δικά του χρόνια.
5. **Πολιτική `sygxronismos`**: χωρίς κωδικό διαβάζει το `<riza>/mathimata.json` και
   συγχρονίζει τα `epilegmeno: true`. Αν δεν υπάρχει κανένα, είναι σφάλμα
   `DEN_VRETHIKE` — όχι κενή επιτυχία. Δεν επιλέγονται μαθήματα από το CLI
   (αυτό είναι έργο της εφαρμογής / διάταξης μαθημάτων).
6. **`programma`** εκτυπώνεται πάντα ως JSON, γιατί το `Apotelesma<unknown>` του
   pipeline δεν έχει δηλωμένη δομή — δεν επιβάλλω φορή μορφή.
7. **Ο κανόνας «μη μοντέλο» στις εντολές χωρίς LLM** είναι σχεδιαστική επιλογή:
   να μην απαιτείται API key για να δεις τα μαθήματά σου.
